### HexaShell

**전체 제목:** HexaShell: A Thin Harness for Exploring the Limits of VLM Agents as Robot Coding Agents

**저자:** Hongcheng Gao 외

**학회/연도:** — / 2026

**arXiv:** [2610.23479v1](https://arxiv.org/abs/2610.23479v1)

**아키텍처:** 두 coding agent가 Codex와 GPT-6-Astra를 medium reasoning effort로 사용한다. 얇은 CLI harness가 명령을 관절 동작으로 변환한다. 실행 agent는 보정된 RGB 영상 3개, 로봇 자세, 관절 각도를 받는다. 도구는 로봇 관측만 사용한다.

**핵심 방법론:** 실행 agent가 도구로 배치를 시도한다. 실패하면 최적화 agent가 로그와 카메라 영상을 읽고 도구를 작성하거나 수정한다. 이후 같은 배치를 다시 실행한다. 도구는 삼각측량과 평면 제약으로 위치를 측정한다. 손목 카메라를 움직여 추가 시점을 얻으며, 이 동작은 행동 예산을 사용한다. 배치 10개에서 개발한 도구를 동결한 뒤 seed 0의 새 배치에서 평가한다.

**로봇 / 과제:** RoboDojo는 Isaac Sim 5.1의 양팔 ARX X5를 위한 시뮬레이션 조작 과제 42개를 포함한다. 과제 그룹은 Generalization, Memory, Long-Horizon, Precision, Open이다. Generalization의 표준 배치와 방해 물체가 있는 배치를 포함하면 총 54개 변형이다.

**주요 contribution:**

- 모델 학습 없이 재사용 로봇 도구를 여러 실행에 걸쳐 유지하고 실패 로그로 수정한다.
- 동일 harness, 모델, 개발 배치에서 RGB 기하 측정과 Depth Anything V2 Base를 비교한다.
- 접촉 유형별 성능과 실패를 분석해 도구의 수행 범위와 한계를 제시한다.

**종합 점수:** 6.9/10.

**한계점:**

- 새 배치 평가도 seed 0 안에 한정된다. Leaderboard baseline과 실행 수 및 seed 조건이 다르다.
- RGB 도구 개발은 이전 depth 도구에서 시작한다. 과제 25개에서 최적화 agent가 성공 판정 조건에 관한 메모도 받는다.
- 고정 harness와의 비교에서는 인터페이스와 도구 사용이 함께 달라진다. 수정 과정만의 효과를 분리하지 못한다.
- 정밀 삽입과 관절 물체 과제는 여전히 어렵다. 실패 분류는 지각·추론·제어 원인을 분리하지 못한다.
- RoboDojo는 모델 지연을 행동 예산에 포함하지 않는다.

## 추론 / 배포

- **추론 지연 시간:** 재평가 실행의 중앙값은 739 s이며, 로봇 동작 시간은 26 s이다. 경과 시간의 대부분은 모델 지연이다.
- **배포 하드웨어:** 실행당 RTX 4090 한 대를 사용하며, 평가는 시뮬레이션에서 수행한다.

## 데이터셋 / 데이터 수집

- **도구 개발:** 모델 학습 없이 seed 0의 과제별 배치 10개를 사용한다. Generalization은 표준 배치 5개와 방해 물체가 있는 배치 5개를 사용한다.
- **평가 데이터:** seed 0의 과제별 새 배치 10개를 사용한다. Generalization은 새 표준 배치 5개와 방해 물체가 있는 새 배치 5개를 사용한다. Benchmark 자체 판정기가 성공을 판단한다.
